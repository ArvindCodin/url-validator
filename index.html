Why regular expressions belong in this course

Every regular expression describes a regular language, and every regular language is accepted by a finite automaton (Kleene's theorem). A URL's syntax has no nesting and needs no counter, so a DFA is enough: the string moves through states for scheme, user info, host, port, path, query and fragment, and it is accepted only if it ends in a final state.

Some parts are pure finite-state counting. A domain label is 1 to 63 characters, so the machine has 63 chained states. A port from 1 to 65535 is a small set of digit-range branches. No memory is needed, so the whole validator stays regular.

How the pattern is built

Each component has its own sub-pattern. They are composed into one expression, and the whole string must match.

Limits

  
A URL that passes is well formed, not necessarily reachable or safe. The pattern accepts localhost and private IPv4 ranges on purpose, so an application that fetches user-supplied URLs still needs an address policy. IPv6 literals and raw Unicode hosts are out of scope.
